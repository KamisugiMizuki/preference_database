Method: dual-agent (A: task-0 设计审查 · B: task-1 detect.mjs CLI) + 父级浏览器证据

## 设计特异性判定

**低特异性（1.5/5）——模板级骨架 + 少量领域贴纸。**

顶部工具栏 + 左侧筛选栏 + 卡片网格 + 7 个标准模态框，与库存管理/客户管理/任务管理工具零差别。产品专属信号仅四样：① S/A/B/C 等级徽章（真实领域设计，全 UI 最像"这个产品"的元素）；② 类型 emoji 图标映射；③ "品鉴日期/个人评价文段"文案；④ 分享卡片水印。蓝色 accent、灰底白卡、8px 圆角、默认字体栈全部是中性系统默认质感。产品性格没有被设计出来，只被文案提及。

## 总体印象

功能完整的个人工具，情感峰值（分享卡片）与结构裂缝（恢复框文案错位、导出谎报范围）并存。最大的机会：把"个人品鉴"的性格做出来，而不是继续当通用 CRUD 模板。

## 优点

1. 双主题 CSS 变量体系完整（prefers-color-scheme 初始检测 + 手动切换 + 暗色 rating 半透明底）
2. 破坏性操作有双保险意识（删除确认框、恢复前自动备份文案）
3. 批量爬图流程是真产品级（进度 i/N、快捷出口齐全）

## 优先问题

1. **[P1] 恢复数据库确认框标题/按钮是"确认删除/删除"**（modal-confirm + restore 复用）——全应用最危险操作被包装成删除语义。修复：按 confirmAction 动态设置标题与按钮文案。
2. **[P1] 导出范围选项是谎言**（scope=selected/filtered 实际都导出全部）——承诺与行为不一致是信任杀手。修复：selected 传 selectedEntryIds，filtered 传 currentSearchQuery。
3. **[P1] 列表静默截断 100 条**（limit:100，计数显示"共 100 条"）——老条目消失无提示。修复：分页/"加载更多"，或诚实显示"显示 100/327 条"。
4. **[P1] 筛选空结果与真·空库共用空状态**（"暂无作品+添加第一个作品"）——用户以为数据丢了。修复：有筛选条件时显示"没有符合筛选条件的作品+清除筛选"。
5. **[P2] 无障碍地基缺失**（outline:none 无 focus-visible、卡片 div 无 tabindex、无 Esc、模态框无 role=dialog、toast 无 aria-live、remove-btn 仅 hover 可见）——键盘/读屏用户无法完成主流程。

## 人物画像红旗

**Alex（效率型）**：零快捷键；详情→编辑四步跳转；每次筛选全量重渲染+base64 整屏等待；批量按钮 disabled 不说原因。

**Sam（无障碍）**：Tab 跳过卡片；无焦点指示；emoji 按钮被读屏读成"倒出的托盘""软盘"；模态框无焦点陷阱无 Esc；16px 勾选框；hover 才出现的删除按钮。

**Riley（边界测试者）**：导出谎报范围；>100 条数据消失且计数误导；筛选归零谎报空库；中文逗号标签解析漏洞；背景点击关闭丢失 2000 字评价；err.message 裸奔。

## 次要观察

- 主题切换不持久化（无 localStorage）
- --genre-* 五个色板 token 全项目零引用（死代码）
- 分享卡片 rating 配色与主 UI 不一致（品牌断裂）
- 导出成功 toast 显示完整路径且 3 秒消失无法复制
- 搜索无防抖；详情图片每次重新 base64 无缓存
- 空类型库时表单 required 卡死新增
- main.ts 残留 DEBUG console.log

## 挑衅性问题

- limit:100 是不是产品在替用户决定"你不该有超过 100 条收藏"？
- "评价文段"必填 + minlength=10——设计在服务品鉴，还是在给用户布置作业？
- 工具栏 7 个图标按钮里哪些真需要常驻？收进菜单后主界面会不会更像这个产品？
